# AI 二维码课堂学情分析系统设计

日期：2026-06-09

修订说明：本次评审补充二维码访问策略、学生身份口径、Excel 字段约束、逐空/逐项计分规则、数值等价安全边界、AI 报告约束和第一版验收标准。

AI 接入补充：第一版 AI 服务明确支持智谱 AI API。智谱接口兼容 OpenAI Chat Completions 格式，系统应通过环境变量配置供应商、Base URL、模型和 API Key，不能把 API Key 写入代码或提交到仓库。

## 目标

做一个轻量 Web 系统，用于数学课堂实时答题和学情分析。教师提前用 Excel 模板整理题目，课堂上生成每题二维码。学生用平板扫码答题，系统自动判分并实时统计。课堂结束后，AI 基于结构化统计数据生成班级学情分析报告。

第一版聚焦一名老师发起一节课堂的完整闭环：

1. Excel 导入题目。
2. 教师校对题目、答案、知识点和判分方式。
3. 发起课堂并生成二维码。
4. 学生扫码输入姓名/学号并答题。
5. 系统自动判分和实时统计。
6. AI 生成学情分析报告。

## 非目标

第一版不做以下能力：

- PPT 自动识别题目作为主流程。
- 开放题、说理题、项目式题的 AI 自动批改。
- 复杂学校/年级/班级/多老师账号体系。
- 完整题库市场或长期资源库。
- 代数恒等式自动化简判定。
- 学生长期账号登录体系。

PPT 可作为后续增强方向，但第一版以 Excel 结构化导入为准。

## 用户与场景

主要用户是数学老师。课堂上，老师在投屏或黑板展示题目二维码，学生用平板扫码进入答题页。系统收集全班答题结果，老师可以实时看到提交情况、正确率、薄弱知识点和分层结果。

学生需要输入姓名和学号/座号。同一课堂内以学号/座号作为学生唯一标识，姓名用于教师端展示。系统在当前设备记住学生身份，后续扫码答题不重复填写。

第一版不要求预置班级名单。教师端能明确显示“已进入课堂但当前题未提交”的学生；如果某个学生从未扫码进入课堂，系统只能通过教师设置的应到人数显示缺口人数，不能自动知道该学生姓名。

第一版题型只覆盖可自动判分的客观题：

- 选择题
- 判断题
- 填空题
- 配对题

3 道提高题若属于应用题、说理题或项目式表达题，第一版不纳入自动正确率统计。它们可以保留为课堂讨论或后续人工批改增强项。

## 技术路线

采用轻量 Web 系统。

### 教师端

教师端提供 5 个核心模块：

1. Excel 导入页：上传标准模板并校验字段。
2. 题目校对页：逐题确认题干、答案、知识点、题型、判分方式和是否纳入统计。
3. 课堂二维码投屏页：显示当前题二维码和题目摘要。
4. 实时答题看板：显示提交人数、正确率、错题热点、已进入但当前题未提交学生。
5. 学情分析报告页：展示学生分层、知识点掌握率、题目错误热点和 AI 诊断结论。

### 学生端

学生端提供扫码答题页：

1. 首次进入课堂时填写姓名和学号/座号。
2. 查看题干和对应答题控件。
3. 提交答案。
4. 系统记录答案、提交时间和判分结果。

### 后端服务

后端负责：

- 课堂管理
- 题目导入和校验
- 二维码链接生成
- 学生身份记录
- 答案提交
- 自动判分
- 实时统计
- AI 报告生成请求
- 报告保存
- 课堂状态和访问令牌校验

### AI 服务提供商

第一版 AI 报告生成默认接入智谱 AI API。接口采用 OpenAI Chat Completions 兼容格式。

配置项：

```text
AI_PROVIDER=zhipu
ZHIPU_API_KEY=<server-side-secret>
ZHIPU_BASE_URL=https://open.bigmodel.cn/api/paas/v4
ZHIPU_CHAT_COMPLETIONS_URL=https://open.bigmodel.cn/api/paas/v4/chat/completions
ZHIPU_MODEL=GLM-4-Flash-250414
```

接入规则：

- API Key 只允许保存在服务端环境变量中。
- 前端、二维码、学生链接、教师链接都不能暴露 API Key。
- 第一版使用非流式调用生成报告。
- 调用超时建议：连接 30 秒，读取 60 秒。
- 遇到 429 限流时，最多重试 2 次，每次等待 1-2 秒。
- 智谱调用失败时，系统保留程序统计报告，并提示教师稍后重新生成 AI 诊断。
- 模型名必须可配置。默认可使用本地指南中验证过的 `GLM-4-Flash-250414`；后续可按智谱官方文档切换到其他模型。

### 数据库

数据库保存：

- 课堂
- 题目
- 学生
- 答题记录
- 知识点统计
- 学情报告

## 二维码和链接策略

第一版生成两类链接：

1. 学生答题链接：每道题一个二维码，对应一条带随机令牌的题目链接。
2. 教师看板链接：单独生成，仅供老师查看实时统计和报告。

链接规则：

- 二维码中不包含学生姓名、学号或答案。
- 学生首次进入课堂时填写姓名和学号/座号，身份保存在当前设备本地。
- 学生答题链接只允许提交对应题目答案。
- 教师看板链接使用独立随机令牌，不能由学生题目链接推导出来。
- 课堂状态分为草稿、进行中、已结束。只有进行中的课堂允许学生提交。
- 课堂结束后，学生链接只读或提示课堂已结束，不再接受新提交。
- 学生重复提交同一题时，第一版默认保留最新一次提交，同时记录提交次数和最后提交时间。

## Excel 模板

第一版 Excel 模板字段：

| 字段 | 说明 |
| --- | --- |
| 题号 | 例如 Q1、Q2 |
| 题型 | 填空、选择、判断、配对 |
| 题干 | 支持多行文本 |
| 小题/空数量 | 填空题为空数量，配对题为配对项数量；选择题、判断题填 1 |
| 选项A | 选择题使用 |
| 选项B | 选择题使用 |
| 选项C | 选择题使用 |
| 选项D | 选择题使用 |
| 标准答案 | 单题或多空答案 |
| 答案分隔符 | 默认 `|` |
| 判分方式 | 文本匹配、数值等价、配对匹配 |
| 知识点 | 可用 `|` 分隔多个知识点 |
| 难度层级 | 基础、提高、拓展 |
| 是否纳入统计 | 是、否 |
| 解析 | 可用于学生反馈或 AI 报告参考 |

字段约束：

- 必填字段：题号、题型、题干、小题/空数量、标准答案、判分方式、知识点、是否纳入统计。
- 选择题必须至少填写选项 A、选项 B。
- 判断题选项固定为正确/错误，Excel 中可不填写选项列。
- 填空题的标准答案数量、判分方式数量必须与小题/空数量一致。
- 配对题的标准答案数量必须与小题/空数量一致。
- `|` 是默认答案分隔符，不建议出现在单个答案正文中。
- 英文逗号 `,` 用于配置同一空的多个等价文本答案，不建议出现在单个文本答案中。
- `是否纳入统计=否` 的题目可以展示和提交，但不参与正确率、知识点掌握率和学生分层。

多空填空题示例：

```text
标准答案：7/8|3/4|5/8|1|1|1|3|加法交换律|加法结合律
判分方式：数值等价|数值等价|数值等价|数值等价|数值等价|数值等价|数值等价|文本匹配|文本匹配
```

配对题示例：

```text
标准答案：①-b|②-a|③-d|④-c|⑤-e
判分方式：配对匹配
```

## 判分规则

### 选择题

学生选择 A/B/C/D。系统与标准答案完全匹配。

### 判断题

学生选择正确/错误。系统与标准答案完全匹配。

### 配对题

学生为每个左侧项目选择右侧选项。系统按 `①-b|②-a` 结构逐项匹配。

### 填空题

每个空对应一个输入框。系统按标准答案分隔符拆分后逐空判分。

填空题支持三类判分方式：

1. 文本匹配：用于知识点名称、运算律名称等文本答案。
2. 数值等价：用于数值、分数、小数、百分数和简单算式答案。
3. 配对匹配：仅用于配对题。

### 计分口径

第一版默认按子项计分：

- 选择题、判断题各 1 个子项。
- 填空题每个空 1 个子项。
- 配对题每个配对项 1 个子项。

统计口径：

- 学生个人正确率 = 正确子项数 / 纳入统计的总子项数。
- 每题正确率默认展示“子项正确率”，即该题所有学生正确子项数 / 该题所有学生应答子项数。
- 每题另展示“整题全对率”，即该题全部子项都答对的学生比例。
- 知识点掌握率默认按绑定该知识点的子项正确率计算。
- 未提交题目不计入该学生已答正确率，但计入课堂提交率和未完成统计。

### 文本匹配

文本匹配做轻量归一化：

- 去掉前后空格。
- 可配置多个等价答案，用英文逗号分隔。
- 不做语义理解。

示例：

```text
标准答案：交换律,加法交换律
```

### 数值等价

数值等价不使用 AI 判分，而使用数学表达式解析库或受控解析器。第一版支持：

- 整数、小数、分数、百分数。
- 四则运算和括号。
- `×`、`x`、`*` 视为乘号。
- `÷`、`/` 作为除法或分数表达。
- `0.5` 等价于 `1/2`。
- `2/4` 等价于 `1/2`。
- `1.0` 等价于 `1`。
- `2+3` 等价于 `5`。
- `(1/8+7/8)` 等价于 `1`。
- `40%` 等价于 `0.4`。

数值等价安全边界：

- 禁止使用 JavaScript `eval` 或任何可执行代码方式解析学生输入。
- 只允许数字、空格、小数点、百分号、括号和四则运算符。
- 输入表达式长度上限为 80 个字符。
- 除数为 0 时直接判为无效答案。
- 优先使用有理数或高精度小数比较；无法精确表示时允许 `1e-9` 以内的误差。
- 表达式解析失败时，该空判错，并在教师端记录为“格式无法识别”。

第一版不支持：

- 单位换算自动判断。
- 文字说理题自动判分。
- 代数恒等式复杂化简。
- 超出四则运算的复杂数学表达式。

## 实时统计

系统实时计算：

- 应答人数
- 提交率
- 每题正确率
- 每题错误率
- 每个空的正确率
- 已进入课堂但当前题未提交学生列表
- 教师设置应到人数后的未进入/未提交缺口数
- 学生个人总正确率
- 知识点掌握率

知识点掌握率基于题目和知识点映射计算。若一道题绑定多个知识点，该题答题结果计入对应知识点统计。

实时性目标：

- 学生提交后，教师看板应在 3 秒内反映统计变化。
- 第一版可以使用轮询、SSE 或 WebSocket，具体实现以后续技术选型为准。
- AI 报告不要求实时生成，课堂结束后由教师手动点击生成。

## 学生分层

按学生总正确率分为四层：

| 层级 | 名称 | 规则 |
| --- | --- | --- |
| A 层 | 优秀拓展层 | 正确率 >= 85% |
| B 层 | 良好提升层 | 70% <= 正确率 < 85% |
| C 层 | 基础夯实层 | 50% <= 正确率 < 70% |
| D 层 | 补差帮扶层 | 正确率 < 50% |

教师端展示每层人数和比例，并参考现有界面风格展示分层诊断。

## 学情分析报告

报告分两步生成：

1. 程序统计：生成可靠的结构化数据。
2. AI 表达：把结构化数据转成教学诊断语言。

程序提供给 AI 的数据包括：

- 班级总人数、提交人数、提交率。
- 平均正确率。
- 每题正确率和错误率。
- 每个知识点正确率。
- 学生分层人数和比例。
- 错误率最高的题目和空格。

AI 生成内容包括：

- 班级整体掌握情况。
- 各层学生特点。
- 薄弱知识点排序。
- 课堂讲评建议。
- 分层作业建议。
- 下一节课复习建议。

AI 输入和输出约束：

- AI 不直接接收完整学生隐私明细，只使用汇总统计数据。
- AI 不得改写原始正确率、人数、题目统计和知识点统计。
- AI 不得编造未在统计数据中出现的学生、题目或知识点。
- AI 输出必须区分“数据结论”和“教学建议”。
- 当提交人数过少或数据不足时，AI 应提示样本不足，而不是给出强诊断。
- 标准答案、知识点和是否纳入统计由教师确认。

## 数据隐私和权限

第一版采用最低必要数据原则：

- 学生端只收集课堂答题所需的姓名、学号/座号和答案。
- 教师看板链接必须使用不可预测随机令牌。
- AI 报告默认只使用汇总统计，不上传学生逐人明细。
- 报告页面展示个人学生数据时，仅在教师端展示。
- 后续若接入正式学校场景，应补充账号登录、权限控制、数据导出和数据删除机制。

## 页面视觉方向

学情分析页参考现有两张图：

- 顶部深绿色标题栏。
- 左侧展示学生分层分布。
- 右侧展示薄弱知识点分布。
- 下方展示 AI 诊断结论。
- 使用清晰的进度条、百分比和人数。

教师端整体应偏课堂工具风格：信息密度适中，适合投屏和快速查看，不做营销式页面。

## 错误处理

Excel 导入校验：

- 缺少必填字段时阻止导入。
- 题型不合法时标红提示。
- 小题/空数量不是正整数时标红提示。
- 标准答案数量与填空数量不一致时提示。
- 判分方式数量与答案数量不一致时提示。
- 选择题缺少必要选项时提示。
- 数值等价答案无法解析时提示，但允许教师改为文本匹配。
- `是否纳入统计` 为空时默认否，并要求教师确认。

课堂答题：

- 学生重复提交时，默认保留最新一次提交，并记录提交时间。
- 学生姓名或学号为空时不能进入答题。
- 同一课堂内同一学号/座号再次进入时，视为同一学生；若姓名不同，教师端提示疑似身份冲突。
- 题目链接或教师看板链接令牌无效时，显示链接不可用。
- 课堂已结束时不能继续提交。
- 已进入课堂但当前题未提交学生显示在教师看板。

AI 报告：

- AI 调用失败时，仍展示程序统计数据。
- 可提供“重新生成报告”按钮。
- AI 输出仅作为教学建议，不覆盖原始统计数据。

## 第一版验收标准

第一版完成时应满足：

- 能导入一份符合模板的 Excel，并生成题目列表。
- 能识别并提示 Excel 中的缺字段、答案数量不匹配、判分方式不匹配。
- 老师能逐题修改题干、答案、知识点、判分方式和是否纳入统计。
- 每道纳入课堂的题目都能生成学生二维码。
- 教师看板链接与学生答题链接互相隔离，学生无法通过题目链接进入教师看板。
- 学生能输入姓名和学号/座号，并完成选择、判断、填空、配对题提交。
- 系统能完成文本匹配、配对匹配和受控数值等价判分。
- 学生重复提交同一题时，系统保留最新答案并记录更新。
- 教师看板能在 3 秒内展示提交人数、正确率和错误热点变化。
- 课堂结束后，系统能生成包含分层分布、知识点掌握率和 AI 诊断结论的报告。
- AI 报告生成能通过服务端环境变量调用智谱 API，前端不暴露 API Key。
- 智谱 API 限流或失败时，系统能保留程序统计并提示重新生成。
- AI 调用失败时，教师仍能查看完整程序统计结果。

## 测试策略

第一版重点测试：

- Excel 模板导入校验。
- 二维码令牌隔离和课堂状态校验。
- 各题型答题和判分。
- 逐空/逐项计分和整题全对率。
- 数值等价判分。
- 数值表达式非法输入、除 0 和超长输入处理。
- 学生身份记录。
- 重复提交处理。
- 教师端实时统计。
- 已进入但未提交学生统计。
- 知识点掌握率计算。
- 学生分层计算。
- AI 报告输入不包含学生逐人明细。
- 智谱 API 配置读取、非流式调用、429 重试和失败降级。
- 前端构建产物和二维码链接不包含 API Key。
- AI 报告失败时的降级展示。

## 后续增强

后续可考虑：
